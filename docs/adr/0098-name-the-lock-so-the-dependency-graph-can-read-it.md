# ADR-0098: Name the lock so the dependency graph can read it

- **Status:** Accepted
- **Date:** 2026-11-24

## Context

ADR-0092 has the image install a lock generated by `uv pip compile`, and holds every
other install to it with `-c` in `requirements-dev.txt`. It named that lock
`requirements.lock`.

GitHub builds the repository's dependency graph by running Dependabot over the
requirements files, and Dependabot fetches the files a list includes or constrains
by only if their names end in `.txt` or `.in`. It never fetched `requirements.lock`,
so pip, reading `requirements-dev.txt`, could not open the constraint, and the
"Graph Update: pip" job failed on every push to `main` with
`Could not open constraint file: ... requirements.lock`. The graph is what
dependency review, the one scheduled check that gates a pull request, compares, so
the Python dependencies it saw were not the ones the image ships.

## Decision

**The lock is `requirements-lock.txt`.** What ADR-0092 decided about it stands: the
image installs it `--no-deps`, `requirements-dev.txt` constrains every other install
with `-c requirements-lock.txt`, and Renovate regenerates it with the command its
header names.

Two things follow from the name ending in `.txt`:

- **Renovate's `pip_requirements` manager matches it by default.** The lock is an
  output, so that manager is turned off for it as it is for `requirements.txt`, and
  only `pip-compile` moves it, by regenerating it.
- **It is a dependency list like the others**, so the audit reads it with
  `-r requirements-lock.txt`: the versions the image ships are the ones held against
  the advisories (ADR-0062).

## Consequences

- The dependency graph, and so dependency review, sees every package the image
  installs, at the version it installs.
- The name is written in the `Dockerfile`, `requirements-dev.txt`, the lock's own
  header (`--output-file=`), `renovate.json5` (the `pip-compile` pattern and the
  `pip_requirements` rule), `audit.yml`, `setup.cfg`'s `also_copy` and
  `.dockerignore`'s opening comment. Renaming it again means all of them;
  `test_the_image_installs_the_runtime_dependencies_only`,
  `test_renovate_can_read_the_lock_s_header`,
  `test_every_install_of_the_tools_is_held_to_the_lock` and
  `test_every_dependency_list_is_audited_or_named` catch the ones that drift.
- A constraint file that is not named `*.txt` or `*.in` brings the failure back:
  any new `-c` or `-r` line must name one that is.
